# Pillar 1.3 — Auth + AppSigner seam (Privy, gated live)

**Status:** design (brainstormed 2026-06-21)
**Depends on:** 1.1 (ledger/users), 1.5 (client→server cutover, `api.ts`/`auth.ts` seam)
**Roadmap:** capability E (auth) + J (wallet port). See `2026-06-20-redline-product-roadmap-design.md` → *The wallet port*.

## Goal

Replace the `x-dev-user` / `web-<uuid>` dev stub with a **pluggable auth seam** and wire a
**real Privy backend** (gated behind a flag), while keeping the dev stub the default for local/test.
Define the `AppSigner` port and capture the Privy embedded Solana wallet address — but **all signing,
custody, deposits, withdrawals, and on-ramp stay dark until Pillar F (money phase)**. Money-last.

## Decisions (locked in brainstorming)

1. **Seam-first, Privy real-but-gated.** Default backend = dev stub (unchanged guest play). Privy
   activates only when `VITE_AUTH=privy` (client) + Privy keys present (server).
2. **Privy is wired live** against a real Privy app the owner provides (`PRIVY_APP_ID`,
   `PRIVY_APP_SECRET`), and verified with a real in-browser login.
3. **Login required at boot** in Privy mode (no guest-then-upgrade merge yet — that's a money-phase
   concern). Dev mode stays guest.
4. **Capture the embedded wallet now.** Add a nullable `wallet_public_key` to `users`; the server
   fetches the user's Privy embedded Solana address (authoritative, via the Privy server SDK) and
   stores it. `AppSigner.publicKey` reads it; **signing throws until F**.
5. **Custom login/account UI**, matching the existing synthwave language in `ui/wallet.ts`.

## Architecture

### Client — `AuthProvider` seam

New `core/auth.ts`:

```ts
export interface AuthProvider {
  ready(): Promise<void>;                 // resolve once an identity exists (privy: after login)
  userId(): string;                       // dev: web-<uuid> · privy: did:privy:<sub>
  authHeaders(): Record<string, string>;  // dev: {"x-dev-user": id} · privy: {authorization: "Bearer <jwt>"}
  login?(): Promise<void>;                // privy: open modal · dev: no-op
  logout?(): Promise<void>;
  walletPublicKey?(): string | null;      // privy embedded address once known; dev: null
}
export function createAuth(): AuthProvider; // picks backend by import.meta.env.VITE_AUTH ('dev' default)
```

Backends:
- `auth/dev.ts` — wraps today's `getDevUserId()`; `authHeaders` → `{ x-dev-user }`. **Default.** No login.
- `auth/privy.ts` — a **React island**, dynamic-imported only when `VITE_AUTH=privy`, so the default
  build ships **zero React**. Mounts `PrivyProvider` (`@privy-io/react-auth`, configured for an
  embedded Solana wallet) on a `#auth-root` div; renders the custom login screen until logged in;
  exposes the Privy access token (JWT) → `authHeaders`, the DID → `userId`, and the embedded wallet
  address → `walletPublicKey`. `ready()` resolves after login.

`api.ts` (refactor): `createApi({ auth })` — replace the hardcoded `x-dev-user` with
`...auth.authHeaders()` on every request. The `userId`/identity concern leaves `api.ts`.

`main.ts` boot: `const auth = createAuth(); await auth.ready(); const me = await api.me();` (rest
unchanged). In Privy mode `ready()` blocks on the login screen; in dev mode it resolves immediately.

### Client — login / account UI (`ui/auth-ui.ts`)

A synthwave login overlay (same panel/gradient/typography idiom as `ui/wallet.ts`):
- **Logged-out (Privy mode, at boot):** full-screen branded gate — logo, one-line pitch, a Privy
  login CTA (Google / email / wallet via Privy's flow). Game stays hidden behind it until ready.
- **Account:** the existing balance chip → wallet page gains an **account row** (Privy avatar/email,
  shortened embedded wallet address with copy, **Log out**). Reuses `wallet.ts` styles + the existing
  `shortAddr`/copy helpers. Dev mode shows a subtle "guest" tag instead of an account.

### Server — dual-path `requireUser`

`http/auth.ts` `makeRequireUser` resolves identity from **either**:
- `authorization: Bearer <jwt>` → `verifyPrivyToken(jwt)` → `externalId = "privy:" + claims.sub`; **or**
- `x-dev-user: <name>` → `externalId = "dev:" + name`, **honored only when `DEV_AUTH` is true**
  (so a production deploy cannot be spoofed with a dev header).

Contract is unchanged: set `req.userId` or reply 401. Then `users.upsertByExternalId(externalId)`.

New `server/src/auth/privy.ts`:
- `verifyPrivyToken(jwt): Promise<{ sub: string }>` — verifies via Privy (`@privy-io/server-auth`,
  app id + verification key). **Injectable** into `makeRequireUser` so tests pass a fake verifier.
- `fetchEmbeddedWallet(did): Promise<string | null>` — Privy server SDK → the user's embedded Solana
  address. Also injectable. Called once, when a Privy user's `wallet_public_key` is still null, and
  stored (not re-fetched per request).

Env (`env.ts`): `PRIVY_APP_ID`, `PRIVY_APP_SECRET` (verification + server API), `DEV_AUTH`
(default true in dev, **false in production**). Boot fails loud if `VITE_AUTH`/Privy expected but
keys are missing — but the dev path must keep working with no Privy keys at all.

### AppSigner port (`core/appsigner.ts`)

```ts
export type SignerBackend = 'dev-null' | 'privy-embedded' | 'mwa-seedvault';
export interface AppSigner {
  readonly backend: SignerBackend;
  publicKey(): string | null;                         // base58; → @solana/kit Address at F
  signTransaction(tx: unknown): Promise<unknown>;     // throws until the money phase
  signMessage(m: Uint8Array): Promise<Uint8Array>;    // throws until the money phase
}
```
- 1.3 ships the interface + a `dev-null` signer (publicKey null, sign throws) and a `privy-embedded`
  signer whose `publicKey()` returns the embedded address but whose `sign*` throw
  `"signing enabled at the money phase"`. No custody, no transactions. `@solana/kit` is **not** added
  yet (publicKey typed as base58 `string`); it arrives with real signing at F.

### Schema

`users`: add `wallet_public_key text` (nullable). One additive Drizzle migration. No backfill.

## Testing (TDD)

- **Server (`auth`/`requireUser`)** — unit tests with an injected fake verifier:
  valid Bearer → `privy:<sub>` user; `x-dev-user` honored when `DEV_AUTH` on; **dev header rejected
  (401) when `DEV_AUTH` off**; missing/garbage token → 401; first Privy login stores
  `wallet_public_key` (injected fake `fetchEmbeddedWallet`), second request does not re-fetch.
- **Client** — `createAuth` backend selection; dev backend `authHeaders` shape; `api.ts` attaches
  `auth.authHeaders()`. The Privy React island + login UI are verified **live in-browser** (real
  login → `did:privy:…` user + embedded wallet in Postgres), since the React island can't run in the
  node test env.
- Full suites + tsc + vite build stay green; the **default (dev) build ships no React** (assert the
  privy module is dynamic-imported).

## Out of scope (money-last / later pillars)

Real signing, deposits/withdrawals, USDC treasury (Pillar F); on-ramp/KYC; **MWA / Seed Vault** (a
Seeker enhancement — verify-on-device, no official Capacitor↔MWA bridge, later); the no-wallet
**lite build**; **guest→Privy balance merge** (a Privy login is a fresh account for now); desktop
keyboard/gamepad work.

## Risks / open items

- **Privy in a Capacitor WebView (iOS `capacitor://`, Seeker)** is a documented verify-on-device
  unknown — 1.3 targets **web only**; the WebView story is deferred with the Seeker shell.
- **React island bundle cost** — mitigated by dynamic-importing it only under `VITE_AUTH=privy`.
- Privy SDK/API shapes are external; verifier + wallet-fetch are isolated behind injectable
  functions so the surface area (and the test mocks) stay small.
